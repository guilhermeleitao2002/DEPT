# DEPT: Defense via Ensemble and Purification Transformer

Code for my MSc thesis at Instituto Superior Técnico (Universidade de Lisboa) and INESC-ID.

DEPT protects an ML-based Network Intrusion Detection System (NIDS) against adversarial traffic generated by TANTGen (Pissarra, 2026). It works in streaming mode: a TCN gives a prediction after every packet, a Random Forest gives one at packet 2 and then every 10 packets, and a small transformer (the meta-learner) combines the two. Flows that the meta-learner flags are then purified by a second transformer (the reconstructor) before they reach the protected NIDS.

## Architecture

```
                         Raw PCAP / Dataset
                               │
                     ┌─────────┴─────────┐
                     │  Packet-to-Tensor  │
                     └────┬─────────┬─────┘
                          │         │
               ┌──────────┘         └──────────┐
               ▼                               ▼
 flow_packets.npy  [P_total, 1090]   rf_checkpoints.npy  [C_total, 24]
 per-packet nPrint + IPAT + Dir      prefix stats at t=2,10,20,30,…
               │                               │
               │   (every packet)              │   (packet 2, then every 10)
               ▼                               ▼
      ┌─────────────────┐             ┌─────────────────┐
      │      TCN        │             │  Random Forest   │
      │ causal dilated  │             │ 200 trees,       │
      │ [B, T, 2] logits│             │ depth=20, leaf=5 │
      └────────┬────────┘             └────────┬─────────┘
               │  dense stream                 │  sparse stream
               └───────────────┬───────────────┘
                                ▼
                    ┌───────────────────────┐
                    │   Meta-Learner        │  flags adversarial flows
                    │  (Mini-Transformer)   │
                    └───────────┬───────────┘
                                │ if adversarial
                                ▼
                    ┌───────────────────────┐
                    │  Reconstructor        │  purifies the flow, which
                    │  (Purification        │  then goes to the protected NIDS
                    │   Transformer)        │
                    └───────────────────────┘
```

Each phase has its own README with details and results: [packet_to_tensor](scripts/packet_to_tensor/README.md) · [adversarial_generation](scripts/adversarial_generation/README.md) · [rf](scripts/rf/README.md) · [tcn](scripts/tcn/README.md) · [metalearner](scripts/metalearner/README.md) · [reconstructor](scripts/reconstructor/README.md) · [gradient_ablation](scripts/gradient_ablation/README.md) · [baseline](scripts/baseline/README.md) · [diffusion_purifier](scripts/diffusion_purifier/README.md).

## Dataset

Ten attack captures from Kitsune, CIC-IDS2017 and CIC-DDoS-2019, each with TANTGen adversarial versions in three modes: `both` (timing and size), `iat` (timing only) and `size` (size only). After tensorization there are 40 sources, 8.62 M flows and 61.5 M packets.

Every flow from the original datasets is labelled **benign** (the protected NIDS already detects those attacks) and every TANTGen flow is **adversarial**. The CIC-DDoS-2019 floods have the most flows (`syn_ddos` alone has 1.34 M adversarial flows per mode), so about 84% of the evaluation flows are adversarial. Accuracy and precision should be read with that in mind.

## Main results

Streaming detection on 1.29 M test flows:

| Metric | RF | TCN | Meta-Learner |
|---|---|---|---|
| First prediction at | packet 2 | packet 1 | packet 1 |
| AUROC@1 | — | 0.8191 | **0.8373** |
| AUROC@2 | **0.9805** | 0.8225 | 0.9099 |
| AUROC@10 | **0.9813** | 0.8371 | 0.9323 |
| AUROC@max | **0.9813** | 0.8386 | 0.9334 |
| EDP median | 2 pkts | **1 pkt** | **1 pkt** |
| Detection rate (p>0.5) | **88.99%** | 78.40% | 77.69% |

The RF is the strongest single model from packet 2 on. The meta-learner is better than the TCN at every packet and gives a verdict at packet 1, with 0.53% false positives on benign flows. All models do poorly on the `_size` variants of the reflection floods and on `mirai`.

Purification (reconstructor, 385 K held-out pairs):

| Metric | Result |
|---|---|
| MSE on perturbed dims, adv → recon | 0.918 → **0.054** |
| TCN `P(adv)`: adv → recon → clean | 0.675 → **0.428** → 0.421 |
| Protocol compliance (`tshark`, realizable packets) | **97.2%** |
| Independent-NIDS detection, adv → purified | 0.781 → **0.906** (clean 0.980), 63.0% restored |

Other studies:

- **Deployment baseline** (phase 8, 2.70 M flow scores): NIDS detection is 0.981 on clean traffic, 0.789 under TANTGen and 0.884 behind DEPT. The attack success rate drops from 21.1% to 11.6%. The gain comes from the variants TANTGen actually evaded (`ddos`, `portscan`); on variants it never evaded, purification can lower detection (`dns_ddos` both/iat, `mirai_size`).
- **Published purifier** (phase 9): the diffusion purifier of Merzouk et al. (DBSec 2025) in the same setup. ML-NIDS attack success on held-out test pairs: 3.3% clean, 29.8% without defense, 38.8% with the diffusion purifier, 17.0% with DEPT.
- **Gradient-guided attacker** (phase 7, RQ1): a white-box attack on the TCN, scored on the RF, the TCN and the full stack at a matched 5% FPR. At small budgets the stack is the hardest target (ASR 1.7% / 4.7% / 8.5% at 8 / 32 / 128 bytes, against 40.5–52.2% for the TCN alone), and 74.5% of flows are never evaded.
- **Per-attack models** (`./run_pipeline.sh --per-attack`): the global and per-attack models are identical on 14 of 30 variants. Per-attack models are better on timing-only variants of the floods; the global model is better on the `_size` variants and on `mirai`.

## Running

```bash
./run_pipeline.sh          # all 9 phases; --per-attack runs phases 3-6 per attack
```

Or phase by phase:

```bash
python3 scripts/adversarial_generation/generate_adversarials.py   # 1. TANTGen adversarial PCAPs
python3 scripts/packet_to_tensor/process_all_attacks.py           # 2. ragged per-flow tensors
python3 scripts/rf/run_rf.py                                      # 3. Random Forest
python3 scripts/tcn/run_tcn.py                                    # 4. TCN
python3 scripts/metalearner/run_metalearner.py                    # 5. meta-learner (needs 3 + 4)
python3 scripts/reconstructor/run_reconstructor.py                # 6. reconstructor
python3 scripts/gradient_ablation/run_gradient_ablation.py        # 7. gradient-guided attacker (RQ1)
python3 scripts/baseline/run_baseline.py                          # 8. deployment baseline
python3 scripts/diffusion_purifier/run_diffusion_purifier.py      # 9. comparison with a published purifier
```

Phases 3–6 read the same tensors and use a flow-level split with `seed=42`. Phases 7–9 evaluate the global models and are skipped in `--per-attack` runs.

Runtime of the full run:

| Phase | Wall clock | Notes |
|---|---|---|
| 1. Adversarial generation | 26.7 h | 10 attacks × 3 modes; `ntp_ddos` alone is 11.9 h |
| 2. Packet-to-Tensor | 11.2 h | 40 sources → 8.62 M flows / 61.5 M packets |
| 3. Random Forest | 2.7 h | includes an 18-point grid search |
| 4. TCN | 25.3 h | early stopping after 10 of 20 epochs |
| 5. Meta-learner | 3.6 h | 20 epochs, best at 17 |
| 6. Reconstructor | 10.0 h | includes realization and NIDS evaluation |
| 7. Gradient-guided attacker | 4.3 h | 9,000 flows × 6 budgets |
| 8. Deployment baseline | 33.6 h | 2.70 M flow scores through the independent NIDS |
| 9. Diffusion-purifier comparison | 15.9 h | overlays 46 min, training 30 min, `t*` sweep 6.9 h, evaluation 7.8 h |

A per-attack run of phases 3–6 adds about 28 h. Its artifacts go to `data/models/per_attack/<attack>/<stage>/`.

The raw captures, PCAPs and tensors are not in this repository (they are hundreds of GB). The repository keeps the configs, logs, metrics, plots and the trained TCN, meta-learner and reconstructor weights.

## Requirements

```bash
sudo apt install -y python3 python3-pip python3-venv python3-dev build-essential git \
                    wireshark-common tshark tcpdump libpcap-dev
pip3 install -r requirements.txt
```

`tshark`/`editcap` filter the CIC-IDS2017 captures by time and check protocol compliance; `tcpdump -c N` caps the large CIC-DDoS-2019 captures; `build-essential` and `python3-dev` are needed for packages that compile, including TANTGen's Cython extension.

GPU training needs an NVIDIA driver compatible with the `torch` build in `requirements.txt` (CUDA 12.4); check with `python3 -c "import torch; print(torch.cuda.is_available())"`.

Phases 1 and 6–9 also need the TANTGen code in a sibling directory, `../Transformer-based_Adversarial_Network_Traffic_Generator` (set by `nids.tantgen_root` in the configs). It provides the generator, the Kitsune and ML-NIDS models and the cicflowmeter version they were trained with. See [`scripts/adversarial_generation/README.md`](scripts/adversarial_generation/README.md).

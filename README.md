# ADEPT — Adaptive Defense via Ensemble and Purification Transformer

Research implementation for my Master Thesis at IST/INESC-ID (Universidade de Lisboa).

ADEPT defends ML-based Network Intrusion Detection Systems (NIDS) against adversarial attacks generated by [TANTGen](../Transformer-based_Adversarial_Network_Traffic_Generator/). Rather than waiting for a flow to finish, the ensemble operates in **streaming mode**: the TCN emits a prediction after every new packet; the Random Forest emits one at packet 2 and then every 10 packets on the growing prefix (the early-2 checkpoint exists so short flows like PortScan — which average ~2 packets — still get an RF verdict). A mini-transformer meta-learner fuses these two complementary streams to trade off early-but-noisy TCN detections against delayed-but-precise RF confirmations.

## Architecture

```
                         Raw PCAP / Dataset
                               │
                     ┌─────────┴─────────┐
                     │  Packet-to-Tensor  │
                     └────┬─────────┬─────┘
                          │         │
               ┌──────────┘         └──────────┐
               ▼                               ▼
 flow_packets.npy  [P_total, 1090]   rf_checkpoints.npy  [C_total, 24]
 per-packet nPrint + IPAT + Dir      prefix stats at t=2,10,20,30,…
               │                               │
               │   (every packet)              │   (early@2, then every 10)
               ▼                               ▼
      ┌─────────────────┐             ┌─────────────────┐
      │      TCN        │             │  Random Forest   │
      │ causal dilated  │             │ 400 trees,       │
      │ [B, T, 2] logits│             │ depth=40, leaf=1 │
      └────────┬────────┘             └────────┬─────────┘
               │  dense stream                 │  sparse stream
               └───────────────┬───────────────┘
                                ▼
                    ┌───────────────────────┐
                    │   Meta-Learner        │  ── Phase 4 (planned)
                    │  (Mini-Transformer)   │
                    └───────────┬───────────┘
                                ▼
                    ┌───────────────────────┐
                    │  Purification         │  ── Phase 5 (planned)
                    │  Transformer          │
                    └───────────────────────┘
```

The two base learners are **temporally complementary by design**: the TCN is dense and early (it flags a flow from its very first packet), while the RF is sparse and precise (it produces an early checkpoint at packet 2, then refreshes every 10 packets, and achieves near-perfect separation at all checkpoints). The meta-learner's role is to learn *when* to trust the early TCN alarm versus wait for RF confirmation — a sequential-fusion problem a transformer is well-suited for.

Paired with **TANTGen** (sibling repo), which generates the adversarial PCAPs that ADEPT learns to detect and denoise. The two systems form a closed attack/defense loop.

## Dataset

Five benign traffic sources (Kitsune / CIC-IDS2017 captures) are paired with TANTGen adversarial variants across three perturbation modes: **both** (timing + size), **iat** (timing only), **size** (payload/size only).

| Source | Flows | Packets |
|---|---:|---:|
| Mirai Botnet (Kitsune) | 32,921 | 764,137 |
| SSDP Flood (Kitsune) | 65,738 | 4,077,266 |
| DDoS (CIC-IDS2017) | 86,272 | 2,151,810 |
| Port Scan (CIC-IDS2017) | 230,156 | 2,026,245 |
| Brute Force FTP+SSH (CIC-IDS2017) | 158,115 | 9,830,521 |
| Brute Force adversarial (×3 modes) | 80 each | ~2,500 each |
| DDoS adversarial (×3 modes) | 1,011 each | ~9,741 each |
| DDoS Kitsune adversarial (×3 modes) | 15,819 each | ~255,827 each |
| Mirai adversarial (×3 modes) | 3,830 each | ~192,755 each |
| PortScan adversarial (×3 modes) | 15,839 each | ~31,885 each |
| SSDP Flood adversarial (×3 modes) | 64,722 each | ~287,921 each |

Under ADEPT's label convention, every Kitsune/CIC-IDS2017 flow is **benign** (the upstream NIDS already handles the raw-dataset attacks) and every TANTGen-generated flow is **adversarial**. ADEPT's specific job is to catch novel TANTGen-style perturbations.

## Base learner results

### Random Forest

Trained on 1.94 M multi-scale prefix checkpoints (cadence: packet 2, then every 10 packets); evaluated on 338 K held-out checkpoints across 125,914 flows. Best configuration: 400 trees, `max_depth=40`, `min_samples_leaf=1`, `class_weight=balanced_subsample`.

| Metric | Value |
|---|---|
| ROC AUC (per-checkpoint) | **0.9990** |
| PR AUC (per-checkpoint) | 0.9975 |
| Recall (adversarial) | 0.9860 |
| Streaming AUROC@2 | **0.9984** |
| Streaming AUROC@10 | **0.9991** |
| Streaming AUROC@max | 0.9992 |
| EDP (median) | **2 packets** |
| Detection rate (p>0.5) | 98.91% |

### Temporal Convolutional Network

Trained on 877 K variable-length flows (truncated at 200 packets during batching); evaluated on 131 K held-out flows. Best epoch 17 / 20.

| Metric | Value |
|---|---|
| Macro F1 | **0.9608** |
| ROC AUC | 0.9857 |
| PR AUC | 0.9807 |
| Streaming AUROC@1 | **0.9493** |
| EDP (median) | **1 packet** |

Architecture: 3 stacked dilated causal TemporalBlocks, channels=[128,128,128], k=3, receptive field=29 packets. 805 K parameters.

### Streaming comparison

| Metric | RF | TCN |
|---|---|---|
| First prediction at | **packet 2** | packet 1 |
| AUROC@1 | — (no prediction yet) | 0.9493 |
| AUROC@2 | **0.9984** | 0.9765 |
| AUROC@10 | **0.9991** | 0.9817 |
| AUROC@max | **0.9992** | 0.9857 |
| EDP median | **2 pkts** | **1 pkt** |
| Detection rate (p>0.5) | 98.91% | 91.74% |

The complementarity is now much tighter: the TCN flags adversarial flows at a median of **1 packet** while the RF reaches AUROC **0.9984** at its very first checkpoint (packet 2) and refines to **0.9991** at packet 10. The RF still loses to the TCN at packet 1 (where RF has no prediction yet) and the TCN still loses to the RF on the per-source metrics where aggregated statistics dominate (e.g. Mirai). The two-packet detection latency for the RF closes most of the previous gap — now the meta-learner's job is mostly about disambiguating disagreement at packets 1–2 and absorbing TCN false alarms at later packets.

### Observations

- **IAT-only perturbation is consistently the hardest mode.** Both models show lower AUROC/F1 for `_iat` variants than `_both` or `_size`. Pure timing perturbation without structural changes is more subtle.
- **PortScan adversarials are now fully covered.** Under the new cadence, every PortScan flow (≥2 packets) gets an RF checkpoint at packet 2. Per-source AUROC@5 = 1.0000 for `portscan_adv_both` and `portscan_adv_iat`, 0.9954 for `portscan_adv_size` — the regime where the RF previously produced *zero* predictions.
- **TCN fails on portscan\_iat** (F1=0.002, AUROC@1=0.789). With ~2 packets per flow there is almost no inter-packet interval to perturb, so IAT-only adversarial PortScan flows look nearly identical to benign ones from the TCN's perspective. Size perturbation (portscan\_size, portscan\_both) works fine (F1≈0.97). The RF now compensates here.
- **Mirai adversarial recall is low for TCN** (0.39–0.51 across all three modes). The RF reaches AUROC 0.99+ on Mirai variants under the new cadence, confirming that aggregated temporal statistics dominate the per-packet sequence for this attack type.
- **RF AUROC@10 dipped slightly (0.9998 → 0.9991)** because the dataset now includes much harder short-flow regimes (PortScan adversarials, brute-force adv) that previously had zero RF predictions and were silently excluded from the metric. The model's effective coverage is dramatically wider, not weaker.

## Quick start

```bash
# 1. Generate TANTGen adversarial PCAPs
python3 scripts/adversarial_generation/generate_adversarials.py

# 2. Build ragged per-flow tensors for all benign + adversarial sources
python3 scripts/packet_to_tensor/process_all_attacks.py --tantgen

# 3. Train + evaluate the Random Forest
python3 scripts/rf/run_rf.py

# 4. Train + evaluate the TCN
python3 scripts/tcn/run_tcn.py

# 5. Train + evaluate the Mini-Transformer meta-learner (consumes the
#    trained RF + TCN; trains on the seed=42 val split out-of-fold for
#    both base learners, evaluates on the test split)
python3 scripts/metalearner/run_metalearner.py
```

Steps 3, 4, and 5 share the same tensor artifacts and the same flow-level split (seed=42). RF and TCN results are directly comparable; the meta-learner consumes both as a stacker over their per-flow streams.

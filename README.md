# DEPT — Defense via Ensemble and Purification Transformer

Research implementation for my Master Thesis at IST/INESC-ID (Universidade de Lisboa).

DEPT defends ML-based Network Intrusion Detection Systems against adversarial traffic generated by [TANTGen](../Transformer-based_Adversarial_Network_Traffic_Generator/) (sibling repo). Rather than waiting for a flow to finish, it operates in **streaming mode**: a TCN emits a prediction after every packet, a Random Forest emits one at packet 2 and then every 10 packets on the growing prefix, and a mini-transformer meta-learner fuses the two — trading early-but-noisy TCN alarms against delayed-but-precise RF confirmations. Flows the ensemble flags are then **purified** by a denoising transformer before reaching the protected NIDS.

## Architecture

```
                         Raw PCAP / Dataset
                               │
                     ┌─────────┴─────────┐
                     │  Packet-to-Tensor  │
                     └────┬─────────┬─────┘
                          │         │
               ┌──────────┘         └──────────┐
               ▼                               ▼
 flow_packets.npy  [P_total, 1090]   rf_checkpoints.npy  [C_total, 24]
 per-packet nPrint + IPAT + Dir      prefix stats at t=2,10,20,30,…
               │                               │
               │   (every packet)              │   (early@2, then every 10)
               ▼                               ▼
      ┌─────────────────┐             ┌─────────────────┐
      │      TCN        │             │  Random Forest   │
      │ causal dilated  │             │ 200 trees,       │
      │ [B, T, 2] logits│             │ depth=20, leaf=5 │
      └────────┬────────┘             └────────┬─────────┘
               │  dense stream                 │  sparse stream
               └───────────────┬───────────────┘
                                ▼
                    ┌───────────────────────┐
                    │   Meta-Learner        │  ── flags adversarial flows
                    │  (Mini-Transformer)   │
                    └───────────┬───────────┘
                                │ if adversarial
                                ▼
                    ┌───────────────────────┐
                    │  Reconstructor        │  ── purifies (denoises) the flow,
                    │  (Purification        │     then feeds the protected NIDS
                    │   Transformer)        │
                    └───────────────────────┘
```

The base learners are **temporally complementary by design**: the TCN is dense and early, the RF sparse and precise. The meta-learner learns *when* to trust which — a sequential-fusion problem a transformer suits well.

Per-module detail lives in each script's README: [packet_to_tensor](scripts/packet_to_tensor/README.md) · [adversarial_generation](scripts/adversarial_generation/README.md) · [rf](scripts/rf/README.md) · [tcn](scripts/tcn/README.md) · [metalearner](scripts/metalearner/README.md) · [reconstructor](scripts/reconstructor/README.md) · [gradient_ablation](scripts/gradient_ablation/README.md) · [baseline](scripts/baseline/README.md) · [diffusion_purifier](scripts/diffusion_purifier/README.md).

## Dataset

Ten benign sources (Kitsune, CIC-IDS2017, CIC-DDoS-2019) each paired with TANTGen adversarial variants in three perturbation modes — **both** (timing + size), **iat** (timing only), **size** (payload/size only). Tensorization yields **40 sources, 8.62 M flows, 61.5 M packets**.

Under DEPT's label convention every raw-dataset flow is **benign** (the upstream NIDS already handles those attacks) and every TANTGen flow is **adversarial** — DEPT's job is specifically to catch novel TANTGen-style perturbations.

The five CIC-DDoS-2019 reflection floods dominate the flow counts (`syn_ddos` alone contributes 1.34 M adversarial flows per mode), so the evaluation pool is **≈83.7% adversarial**. Base-rate-dependent figures (accuracy, precision) must be read with that prior; the comparable cross-model axis is the flow-level streaming metrics.

## Results

### Streaming comparison (flow-level, like-for-like — 1.29 M test flows)

| Metric | RF | TCN | Meta-Learner |
|---|---|---|---|
| First prediction at | packet 2 | **packet 1** | **packet 1** |
| AUROC@1 | — | 0.8191 | **0.8373** |
| AUROC@2 | **0.9805** | 0.8225 | 0.9099 |
| AUROC@10 | **0.9813** | 0.8371 | 0.9323 |
| AUROC@max | **0.9813** | 0.8386 | 0.9334 |
| EDP median | 2 pkts | **1 pkt** | **1 pkt** |
| Detection rate (p>0.5) | **88.99%** | 78.40% | 77.69% |

The **RF is the strongest single stream** from its first checkpoint onward. The meta-learner sits between the two base learners, beats the TCN at every horizon, and is the only model pairing a packet-1 verdict with near-RF late accuracy at a 0.53% benign FPR. What the stack buys over just using the RF is therefore **not raw AUROC** — it is (i) a verdict one packet earlier and (ii) robustness against gradient-guided evasion.

Three findings recur across every stage:

- **The reflection floods' `_size` variants are a representation-level blind spot.** RF and meta score *below chance* against same-base benign (0.21–0.50): TANTGen's size edits on these single-response UDP floods make a flow look *more* like generic benign traffic than the source's own benign flows do. Detecting them needs a signal the prefix statistics don't carry.
- **Timing-only edits split the two base learners.** The TCN is weak on `_iat` variants of TCP sources (`portscan_iat` 0.65) and blind on all four reflection floods (≈0.50 every mode); the RF's aggregate IPAT statistics handle them easily (≥0.99 except `mirai_iat` 0.92). This is exactly the complementarity the fusion exploits.
- **Mirai is the hardest source for every model** (RF 0.83–0.93, TCN 0.68–0.72, meta 0.72–0.73) and the weakest reconstruction too — short, bursty IoT flows.

### Purification (reconstructor, 385 K held-out pairs)

| Metric group | Result |
|---|---|
| **Reconstruction** — MSE on perturbed dims, adv → recon | 0.918 → **0.054** (17.0×) |
| **Purification gain** — TCN `P(adv)`: adv → recon → clean | 0.675 → **0.428** → 0.421 (gain 0.247) |
| **Protocol compliance** — `tshark` on realizable packets | **97.2%** |
| **Independent-NIDS restoration** — detection adv → purified | 0.781 → **0.906** (clean 0.980); **63.0% restored** |

The headline is restoration through the **independent** NIDS each attack was built to evade (Kitsune / TANTGen's ML-NIDS) — the TCN gain is DEPT's own detector and is kept only as an in-distribution sanity check. Kitsune-family detection is restored 0.019 → 0.792 against a 0.793 clean ceiling (99.9%); ML-NIDS 0.808 → 0.910 vs 0.987 (57.1%). The effect is strongly attack-dependent: strong restoration where TANTGen actually evaded (`ddos`, `portscan`, `ssdp_flood_iat`, `syn_ddos_size`), a no-op where it never did, and *harmful* on `dns_ddos` both/iat, `portscan_iat` and `mirai_size`.

### Deployment baseline (phase 8) — 2.70 M flow-scores

Overall NIDS detection: **0.981 clean / 0.789 under TANTGen / 0.884 behind DEPT** — attack success drops from 21.1% to 11.6% (**−9.5 points, 49.3% of destroyed detection restored**). The gain is carried entirely by the six variants TANTGen actually evaded (`ddos` both/size +60/+67, `portscan` both/size +67/+47); on sources it never evaded, the over-eager gate purifies still-detected flows into evading ones (`dns_ddos` both/iat −22.5/−22.7, `mirai_size` −23.9). A gate predicting *whether purification will help* — rather than merely whether a flow is adversarial — is the obvious next step.

### Against a published purifier (phase 9) — held-out test pairs

DEPT's reconstructor vs the diffusion purifier of Merzouk et al. (DBSec 2025), swapped into the phase-8 harness (same flows, realization and NIDS). ML-NIDS attack success: **3.3% clean / 29.8% no defense / 38.8% diffusion / 17.0% DEPT**. Where TANTGen evaded, DEPT restores **63.5%** of the lost detection and the diffusion purifier **0.5%**; no diffusion step helps (`t*` = 2, the least noise in the grid). The diffusion purifier is ahead only on variants TANTGen never evaded (`dns_ddos` ×3, `brute_force_both`), where its near-identity output is the best possible move, and its extra damage on timing-sensitive floods is partly an artifact of the timing encoding. The same ranking holds on the strict, gated and record-count-stable subsets. Details and caveats: [diffusion_purifier README](scripts/diffusion_purifier/README.md).

### Gradient-guided evasion, RQ1 (phase 7) — 9,000 flows × 6 budgets

White-box PGD on the TCN, increase-only padding + delay, matched 5% FPR thresholds. The TCN alone folds at the smallest budget (ASR 40.5%, median evasion budget b8, only 45.5% never evaded). The RF resists (b512, 64.0%), and the **stack is strictly the hardest target at realistic budgets** — ASR 1.7% / 4.7% / 8.5% at b8/b32/b128 vs 8.6% / 10.7% / 13.1% for the RF alone, with 74.5% of flows never evaded. TANTGen's own perturbations (~30 pad-bytes/packet) sit in exactly the b32–b128 regime where the stack concedes ≤8.5%. Two honest footnotes: the attacker has no gradient path through the RF (which is precisely the stack's advantage), and query-matched *random* search evades the TCN slightly better than PGD at every budget — under increase-only constraints the search space, not the gradient, is the binding constraint.

### Global vs per-attack specialists

Phases 3–6 were also run once per attack (`./run_pipeline.sh --per-attack`). Specialists and the global model are **identical on 14 of 30 slices**; where they differ they differ by a lot. Specialists win on the `both`/`iat` modes of reflection floods and on timing-only edits (`ntp_ddos` +0.347, `syn_ddos_iat` +0.194, `ssdp_ddos` +0.073, `portscan_iat` +0.066) by keying on one flood's own timing signature instead of averaging over nine unrelated benign pools. The global model wins on the reflection-flood `_size` variants and on `mirai` — where the per-attack meta-learner scores 0.705 against its own RF's 0.889, i.e. with a single attack's data the fusion layer never learns to defer to the forest.

**Reading for deployment:** a global model is the right default — one model, no routing, never a catastrophic loss — but timing-only modes of high-rate floods are worth a specialist if that traffic matters. The `_size` blind spot appears in *both* regimes, so it is a property of the feature representation, not of training scope.

## Quick start

```bash
./run_pipeline.sh          # all 9 phases; --per-attack runs phases 3-6 per attack
```

Or phase by phase:

```bash
python3 scripts/adversarial_generation/generate_adversarials.py   # 1. TANTGen adversarial PCAPs
python3 scripts/packet_to_tensor/process_all_attacks.py           # 2. ragged per-flow tensors
python3 scripts/rf/run_rf.py                                      # 3. Random Forest
python3 scripts/tcn/run_tcn.py                                    # 4. TCN
python3 scripts/metalearner/run_metalearner.py                    # 5. meta-learner (needs 3 + 4)
python3 scripts/reconstructor/run_reconstructor.py                # 6. purification transformer
python3 scripts/gradient_ablation/run_gradient_ablation.py        # 7. RQ1 evasion cost
python3 scripts/baseline/run_baseline.py                          # 8. deployment baseline
python3 scripts/diffusion_purifier/run_diffusion_purifier.py      # 9. vs a published purifier
```

Phases 3–6 share the same tensors and the same flow-level split (`seed=42`), so all results are directly comparable and no test flow leaks into any model's training set. Phases 7–9 are comparison studies over the global models (skipped in `--per-attack` runs): phase 7 asks whether heterogeneous stacking raises the cost of a *gradient-guided* attacker — something black-box TANTGen structurally cannot measure — phase 8 asks whether DEPT in front of a real NIDS restores the detection TANTGen destroyed, and phase 9 swaps DEPT's purifier for a published one (the diffusion purifier of Merzouk et al., DBSec 2025) in that same setting.

### Runtime of the full run

| Phase | Wall clock | Notes |
|---|---|---|
| 1. Adversarial generation | 26.7 h | 10 attacks × 3 modes; `ntp_ddos` alone is 11.9 h |
| 2. Packet-to-Tensor | 11.2 h | 40 sources → 8.62 M flows / 61.5 M packets |
| 3. Random Forest | 2.7 h | incl. 18-point grid search |
| 4. TCN | 25.3 h | 24.7 h train (early-stopped at epoch 6 of 10) |
| 5. Meta-learner | 3.6 h | 20 epochs, best at 17 |
| 6. Reconstructor | 10.0 h | + realization / NIDS evaluation |
| 7. Gradient ablation | 4.3 h | 9,000 flows × 6 budgets × 3 targets × 2 attackers |
| 8. Deployment baseline | 33.6 h | 2.70 M flow-scores through the independent NIDS |
| 9. Diffusion-purifier comparison | 15.9 h | overlays 46 min, training 30 min, `t*` sweep 6.9 h, evaluation 7.8 h |

A per-attack run of phases 3–6 over all ten attacks adds roughly 28 h (largest: `syn_ddos` 8.5 h; smallest: `mirai` 29 min), with artifacts under `data/models/per_attack/<attack>/<stage>/`.

## Requirements

```bash
sudo apt install -y python3 python3-pip python3-venv python3-dev build-essential git \
                    wireshark-common tshark tcpdump libpcap-dev
pip3 install -r requirements.txt
```

`tshark`/`editcap` handle CIC-IDS2017 time filtering; `tcpdump -c N` packet-caps the large CIC-DDoS-2019 captures (fast even on the 37 GB NTP file); `build-essential` + `python3-dev` cover pip wheels that must compile, including TANTGen's Cython build.

GPU training needs NVIDIA drivers and a CUDA runtime matching the installed `torch` wheel — verify with `nvidia-smi` and `python3 -c "import torch; print(torch.cuda.is_available())"`. TANTGen generation needs additional setup (sibling repo install, Cython build); see [`scripts/adversarial_generation/README.md`](scripts/adversarial_generation/README.md).

# ADEPT — Adaptive Defense via Ensemble and Purification Transformer

Research implementation for my Master Thesis at IST/INESC-ID (Universidade de Lisboa).

ADEPT defends ML-based Network Intrusion Detection Systems (NIDS) against adversarial attacks generated by [TANTGen](../Transformer-based_Adversarial_Network_Traffic_Generator/). Rather than waiting for a flow to finish, the ensemble operates in **streaming mode**: the TCN emits a prediction after every new packet; the Random Forest emits one every 10 packets on the growing prefix. A mini-transformer meta-learner fuses these two complementary streams to trade off early-but-noisy TCN detections against delayed-but-precise RF confirmations.

## Architecture

```
                         Raw PCAP / Dataset
                               │
                     ┌─────────┴─────────┐
                     │  Packet-to-Tensor  │
                     └────┬─────────┬─────┘
                          │         │
               ┌──────────┘         └──────────┐
               ▼                               ▼
 flow_packets.npy  [P_total, 1090]   rf_checkpoints.npy  [C_total, 24]
 per-packet nPrint + IPAT + Dir      prefix stats at t=10,20,30,…
               │                               │
               │   (every packet)              │   (every 10 packets)
               ▼                               ▼
      ┌─────────────────┐             ┌─────────────────┐
      │      TCN        │             │  Random Forest   │
      │ causal dilated  │             │ 400 trees,       │
      │ [B, T, 2] logits│             │ balanced_subsample│
      └────────┬────────┘             └────────┬─────────┘
               │  dense stream                 │  sparse stream
               └───────────────┬───────────────┘
                                ▼
                    ┌───────────────────────┐
                    │   Meta-Learner        │  ── Phase 4 (planned)
                    │  (Mini-Transformer)   │
                    └───────────┬───────────┘
                                ▼
                    ┌───────────────────────┐
                    │  Purification         │  ── Phase 5 (planned)
                    │  Transformer          │
                    └───────────────────────┘
```

The two base learners are **temporally complementary by design**: the TCN is dense and early (it flags a flow from its very first packet), while the RF is sparse and precise (it waits for 10-packet prefixes but achieves near-perfect separation at that checkpoint). The meta-learner's role is to learn *when* to trust the early TCN alarm versus wait for RF confirmation — a sequential-fusion problem a transformer is well-suited for.

Paired with **TANTGen** (sibling repo), which generates the adversarial PCAPs that ADEPT learns to detect and denoise. The two systems form a closed attack/defense loop.

## Dataset

Five benign traffic sources (Kitsune / CIC-IDS2017 captures) are paired with TANTGen adversarial variants across three perturbation modes: **both** (timing + size), **iat** (timing only), **size** (payload/size only).

| Source | Flows | Packets |
|---|---:|---:|
| Mirai Botnet (Kitsune) | 32,921 | 764,137 |
| SSDP Flood (Kitsune) | 65,738 | 4,077,266 |
| DDoS (CIC-IDS2017) | 86,272 | 2,151,810 |
| Port Scan (CIC-IDS2017) | 230,156 | 2,026,245 |
| Brute Force FTP+SSH (CIC-IDS2017) | 158,115 | 9,830,521 |
| Brute Force adversarial (×3 modes) | 80 each | ~2,500 each |
| DDoS adversarial (×3 modes) | 1,011 each | ~9,741 each |
| DDoS Kitsune adversarial (×3 modes) | 15,819 each | ~255,827 each |
| Mirai adversarial (×3 modes) | 3,830 each | ~192,755 each |
| PortScan adversarial (×3 modes) | 15,839 each | ~31,885 each |
| SSDP Flood adversarial (×3 modes) | 64,722 each | ~287,921 each |

Under ADEPT's label convention, every Kitsune/CIC-IDS2017 flow is **benign** (the upstream NIDS already handles the raw-dataset attacks) and every TANTGen-generated flow is **adversarial**. ADEPT's specific job is to catch novel TANTGen-style perturbations.

## Base learner results

### Random Forest

Trained on 1.8 M multi-scale prefix checkpoints; evaluated on 229 K held-out checkpoints. Best configuration: 400 trees, unbounded depth, `min_samples_leaf=2`, `class_weight=balanced_subsample`.

| Metric | Value |
|---|---|
| ROC AUC | **0.9887** |
| PR AUC | 0.9596 |
| Recall (adversarial) | 0.9745 |
| Streaming AUROC@10 | **0.9998** |
| EDP (median) | 10 packets |

### Temporal Convolutional Network

Trained on 877 K variable-length flows (truncated at 200 packets during batching); evaluated on 131 K held-out flows. Best epoch 17 / 20.

| Metric | Value |
|---|---|
| Macro F1 | **0.9608** |
| ROC AUC | 0.9857 |
| PR AUC | 0.9807 |
| Streaming AUROC@1 | **0.9493** |
| EDP (median) | **1 packet** |

Architecture: 3 stacked dilated causal TemporalBlocks, channels=[128,128,128], k=3, receptive field=29 packets. 805 K parameters.

### Streaming comparison

| Metric | RF | TCN |
|---|---|---|
| First prediction at | packet 10 | packet 1 |
| AUROC@1 | — (no prediction yet) | 0.949 |
| AUROC@10 | **0.9998** | 0.982 |
| AUROC@max | **0.9998** | 0.986 |
| EDP median | 10 pkts | **1 pkt** |
| Detection rate (p>0.5) | 99.0% | 91.7% |

The complementarity is confirmed: the TCN flags adversarial flows at a median of **1 packet** while the RF achieves AUROC **0.9998** at its first 10-packet checkpoint. Neither model dominates both dimensions simultaneously — the expected precondition for a useful meta-learner.

### Observations

- **IAT-only perturbation is consistently the hardest mode.** Both models show lower AUROC/F1 for `_iat` variants than `_both` or `_size`. Pure timing perturbation without structural changes is more subtle.
- **PortScan flows are too short for RF checkpoints.** PortScan flows average ~2 packets, so no flow reaches the 10-packet threshold. The RF produces zero predictions for PortScan; the TCN covers them from packet 1.
- **TCN fails on portscan\_iat** (F1=0.002, AUROC@1=0.789). With ~2 packets per flow there is almost no inter-packet interval to perturb, so IAT-only adversarial PortScan flows look nearly identical to benign ones from the TCN's perspective. Size perturbation (portscan\_size, portscan\_both) works fine (F1≈0.97).
- **Mirai adversarial recall is low for TCN** (0.39–0.51 across all three modes). The RF reaches AUROC 0.85–0.999 on Mirai variants, suggesting that the aggregated temporal statistics are more informative than the per-packet sequence for this attack type.
- **RF overall precision appears low** (0.16) but this reflects the 93.5% benign composition of the test checkpoint pool, not poor discrimination. ROC AUC (0.9887) and per-source balanced metrics are the meaningful indicators.

## Requirements

```bash
pip3 install -r requirements.txt
sudo apt install wireshark-common -y   # editcap — CIC-IDS2017 time filtering
```

For TANTGen adversarial generation, additional setup is needed (sibling repo install, Cython build); see [`scripts/adversarial_generation/README.md`](scripts/adversarial_generation/README.md).

## Quick start

```bash
# 1. Generate TANTGen adversarial PCAPs
python3 scripts/adversarial_generation/generate_adversarials.py

# 2. Build ragged per-flow tensors for all benign + adversarial sources
python3 scripts/packet_to_tensor/process_all_attacks.py --tantgen

# 3. Train + evaluate the Random Forest
python3 scripts/rf/run_rf.py

# 4. Train + evaluate the TCN
python3 scripts/tcn/run_tcn.py
```

Steps 3 and 4 share the same tensor artifacts and the same flow-level split (seed=42), so RF and TCN results are directly comparable.
